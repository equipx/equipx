# Releasing EquipX

## Android: signed release APK

### 1. Bump the version
Edit `android/app/build.gradle.kts` (`defaultConfig`): currently `versionCode = 1`, `versionName = "0.1.0"`. Increase `versionCode` by 1 for every build you install over an earlier one; set `versionName` to the human version (e.g. `0.2.0`).

### 2. Prepare content and tests
```bash
npm run sync
cd android
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew testDebugUnitTest
```

### 3. Keystore (owner only)
The project owner creates the keystore in Android Studio: Build > Generate Signed App Bundle / APK > APK > Next > Create new... Choose a location outside the repo (e.g. `~/keystores/equipx-release.jks`), a strong store and key password, alias such as `equipx`, validity 25+ years.
- **Never commit** the keystore, passwords or a `keystore.properties` file. `.gitignore` covers `.env*` but not `*.jks`: keep it out of the repo directory entirely.
- Back up the keystore and passwords in a password manager. If lost, updates over an installed build are impossible.

### 4. Build the APK
Build > Generate Signed App Bundle / APK > APK > choose the keystore, enter passwords, build variant **release**, signature versions V1 and V2 > Create. The APK appears in `android/app/release/` (Android Studio shows a Locate link).

### 5. Test the install on a phone
```bash
~/Library/Android/sdk/platform-tools/adb install -r android/app/release/app-release.apk
```
(Uninstall a debug build first: it has a different signature.) Then check: splash and login, camera permission and scan chip (or manual choose), 3D explorer renders (the main release risk: shrinking can break WebView assets or serialization, so test every screen), a procedure, a quiz, troubleshoot, offline in airplane mode. Xiaomi phones: see MIUI notes in `docs/RUNNING.md`.

Distribute the APK file directly (cloud drive or USB) and tell testers to allow install from unknown sources.

## Admin panel

### Option A: Vercel
1. Push the repo to https://github.com/equipx/equipx.
2. Vercel > Add New Project > import the repo; set **Root Directory** to `admin`. Framework: Next.js (auto-detected); build `npm run build`.
3. Environment Variables (Production and Preview), only if using Supabase mode:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (anon key only; never the service-role key)
   Leave both unset to deploy in mock mode.
4. Deploy. In Supabase: Authentication > URL configuration, add the Vercel URL as an allowed redirect/site URL.
5. Verify: log in as a teacher, open Equipment and Results.
`admin/public/models/` and `admin/src/data/seed/` are generated by `npm run sync`: run it and commit the output before deploying so the 3D previews work.

### Option B: local run
```bash
cd admin && npm install && npm run build && npm run start   # http://localhost:3000
```
Or `npm run dev`. Use this for the faculty demo if there is no reliable internet.
